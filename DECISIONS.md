# Решения (ADR-лайт)

| # | Решение | Почему | Альтернативы |
| :- | :--- | :--- | :--- |
| 1 | Python, CLI + простой веб на стандартной библиотеке | Команда знает Python; минимум зависимостей; запуск у жюри одной командой | Node, Streamlit, FastAPI (лишние зависимости) |
| 2 | Конвейер «правила + LLM + проверка цитат + критик + уточнитель» | Закрывает все 4 критерия жюри; каждый этап тестируется отдельно | Один большой промпт (выдуманные цитаты), мультиагентный «чат» (непредсказуемо, дорого по квотам) |
| 3 | Нарезка кодом, а не LLM | Воспроизводимость и точные номера строк для каждого требования | Нарезка LLM: нестабильна между прогонами |
| 4 | Цитаты проверяет код, неподтверждённые замечания отбрасываются | Главный риск LLM — галлюцинации; ТЗ требует привязки к месту | Доверять модели |
| 5 | Gemini 2.5 Flash по умолчанию, REST без SDK | Бесплатный тариф, большой контекст; REST проще тестировать и не зависит от версий SDK | google-genai SDK |
| 6 | Поддержка OpenAI-совместимых API | Запасной вариант при лимитах Gemini; локальные модели | Только Gemini |
| 7 | Режим «только правила» | Агент полезен без ключа; демонстрация при сбое сети | Падать без ключа |
| 8 | Отчёт MD (основной) + HTML + JSON | MD — для сдачи и GitHub; HTML — для демо; JSON — для интеграций | PDF-отчёт (лишняя зависимость) |
| 9 | PDF: восстановление заголовков по размеру шрифта и таблиц через pdfplumber | Без структуры нарезка PDF теряет разделы | Плоский текст |
| 10 | Интерактивные ответы автора (CLI `-i`, `--answers`, веб) | Критерий жюри «уточнение»: агент не только спрашивает, но и учитывает ответы | Только список вопросов |
