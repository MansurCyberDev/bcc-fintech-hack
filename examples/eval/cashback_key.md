# Эталон для `cashback.md` (для проверки агента людьми, агент его не читает)

Документ написан командой специально для проверки агента на «незнакомом» тексте. В него заложено 15 дефектов.

| # | Дефект | Где | Кто должен найти |
| :- | :--- | :--- | :--- |
| E-01 | КБ-3 (излишек переносится) противоречит КБ-4 (при превышении начисления нет) | КБ-3, КБ-4 | LLM |
| E-02 | Критерий 1: 5% от 2 000 ₸ = 100 ₸, а ожидается 200 ₸ | критерии приёмки, КБ-1 | LLM |
| E-03 | Критерий 2: начисление сразу при покупке, а по КБ-2 — в последний день месяца | критерии приёмки, КБ-2 | LLM |
| E-04 | «быстро» в КБ-5 | КБ-5 | правила |
| E-05 | «удобно» в нефункциональных требованиях | НФТ | правила |
| E-06 | Сумма покупки в тенге, кешбэк в тиынах | данные | правила |
| E-07 | GET для подключения (изменение состояния) | API | правила |
| E-08 | clientId: integer в запросе, string в ответе | API | правила |
| E-09 | «ENABLED и т.д.» — перечень статусов не задан | API | правила |
| E-10 | 500: TBD | API | правила |
| E-11 | Нет версии и даты документа | весь документ | правила |
| E-12 | Процент кешбэка передаёт клиент (`percent`) — может поставить любой | API | LLM |
| E-13 | Нет метода отключения и чтения накопленного кешбэка (а КБ-5 его показывает) | API vs КБ-5 | LLM |
| E-14 | Не описаны ошибки 4xx | API | правила |
| E-15 | Не описаны возвраты покупок и что считается «дебетовой картой» | КБ-1, КБ-2 | LLM |
