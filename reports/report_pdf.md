#### D-32 🟡 Неоднозначный термин и противоречие по времени доставки

*Незначительно · Однозначность (ISO 29148 5.2.5 c; IEEE 830 4.3.2) · требования: R-01 · найдено: LLM*

## Приложение Б. Замечания, отклонённые критиком

Эти замечания модель-аналитик предложила, но независимый критик счёл их ложными. Приведены для прозрачности.

- Нарушение семантики HTTP в дочерней спецификации API (R-12) — причина: Дублирует замечание L-08, в котором приведены более точные цитаты непосредственной спецификации API.
- Использование HTTP GET для модификации данных (R-25) — причина: Дублирует замечание L-08 о нарушении HTTP-семантики при использовании метода GET для сохранения настроек.
- Не определено поведение при снижении порога ниже текущих расходов (R-26) — причина: Дублирует замечание L-15 о неопределённости логики при снижении порога ниже текущих расходов.
- Неоднозначность разделения ошибок между кодами 400 и 200 (R-39) — причина: Дублирует замечание L-25 и L-23 в части нечеткости разграничения ответов 400 и 200 ERROR.
- Несоответствие типов данных в запросе и JSON-ответе (R-40) — причина: Проблема надумана: в таблице спецификации ответа (стр. 174–175) для полей amount и enabled явно указан тип string, поэтому пример ответа ей соответствует.
- Неполное описание условий и структуры ответа ошибки 500 (R-43) — причина: Пожелание о наличии traceId/correlationId является детализацией реализации и не противоречит требованиям.

## Приложение В. Методика

1. **Чтение и нарезка** выполняются кодом (без LLM): результат воспроизводим, у каждого требования есть номер строки.
2. **Правила** (код) ищут формальные дефекты: размытые слова, заглушки, пустые поля, неатомарность, HTTP-семантику, несогласованные типы и единицы, коды ответа, границы диапазонов, версию документа, согласования.
3. **LLM-аналитик** проверяет каждое требование по 9 критериям ISO 29148 п. 5.2.5 и набор целиком по п. 5.2.6 / IEEE 830 п. 4.3.
4. **Проверка цитат кодом**: замечание попадает в отчёт, только если его цитата найдена в документе.
5. **Критик** (второй проход LLM) отсеивает ложные срабатывания; дубли правил и LLM сливаются.
6. **Уточнитель** превращает дефекты в вопросы автору с вариантами ответа; в интерактивном режиме ответы применяются.

*Отчёт сформирован агентом автоматически и вручную не редактировался.*
